## 2026-08-04 - Enforcing IMDSv2 and Storage Encryption on EC2 Infrastructure
**Vulnerability:** EC2 instances deployed without mandatory IMDSv2 (Instance Metadata Service Version 2) tokens and without root volume encryption. This exposes the infrastructure to SSRF-based metadata credentials theft and physical or localized storage compromise.
**Learning:** Legacy configurations and boilerplate code (e.g. `fastapi_server_test_instance`) often omit secure-by-default parameters, relying on outdated defaults. Furthermore, invalid HCL syntax (such as using `value` instead of `default` inside variables.tf) blocks OpenTofu formatting and static analysis checks, which prevents automatic validation pipelines from identifying these architectural gaps.
**Prevention:** Ensure all future EC2 configurations explicitly specify `metadata_options { http_tokens = "required" }` and `root_block_device { encrypted = true }`. Mandate strict adherence to OpenTofu HCL syntax standards by integrating `tofu validate` into pre-deployment pipelines, preventing unvalidated blocks from being committed.
