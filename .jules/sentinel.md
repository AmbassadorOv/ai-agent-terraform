## 2025-02-15 - Enforcing IMDSv2 and Root Volume EBS Encryption on EC2 Instances
**Vulnerability:** The EC2 instances configured in `environments/swarms-aws-agent-api/dev/us-east-1/components/machine_image/main.tf` allowed IMDSv1 by default (as `http_tokens` was not set to `required`) and lacked root volume encryption. IMDSv1 is vulnerable to SSRF (Server-Side Request Forgery) attacks where an attacker can retrieve AWS IAM credentials. Unencrypted root volumes pose a risk of unauthorized access to sensitive resting data.
**Learning:** Legacy configuration files often omit newer security practices, such as IMDSv2 token enforcement and default EBS encryption, to simplify setups or preserve backwards compatibility. However, in secure deployments, defense-in-depth requires explicitly overriding these defaults in HCL resources.
**Prevention:** Always enforce IMDSv2 by adding a `metadata_options` block with `http_tokens = "required"`, and configure a `root_block_device` block with `encrypted = true` on all `aws_instance` resources. Use compliance checkers or automated linting tools to verify resource compliance before merging changes.
